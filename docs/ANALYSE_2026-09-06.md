## 3. Datagrunnlag — hva finnes og hva mangler

### 3.1 Tyrving: klart

`poengtabell-tyrvingtabellen - redigerbar.xlsx` har 20 ark (Gutter/Jenter 10–19 år) **med levende Excel-formler**, f.eks. for 60 m G15:

```
M = sekunder×100, N = 7.55×100, O = N−M, P = 1000 + O×2.7, Poeng = IF(P<0,0,ROUNDDOWN(P,0))
```

Det betyr at regnearket kan brukes som **automatisk oracle**: skriv inn resultater i input-cellene, rekalkuler med LibreOffice headless (`soffice --convert-to`), les ut poeng. Da får du ~1600 fasitverdier uten håndarbeid, og de er uavhengige av Python-implementasjonen. Dette er den viktigste enkeltbrikken for loopen.

Merk: DOC/PDF-filene har trolig tekstreglene (80 %-grense, manuell tidtaking, avrunding) som ikke ligger i formlene. De må leses én gang og gjøres om til eksplisitte testcaser.

### 3.2 Masters og mangekamp: mangler alt

| System | Trengs | Kilde | I mappen? |
|---|---|---|---|
| WA Scoring Tables 2025 | A/B/C-konstanter per øvelse/kjønn, eller de fulle tabellene | worldathletics.org (PDF) | Nei |
| WA Combined Events | Formelkonstantene for femkamp/sjukamp/tikamp (offisielt publisert, stabile siden 1984/85) | WA Technical Rules / PDF | Nei |
| WMA Age Factors 2023 | Faktortabell per alder/kjønn/øvelse | world-masters-athletics.org / howardgrubb.co.uk | Nei |
| NFIF Masters mangekamptabell | Excel menn + kvinner | friidrett.no → Poengtabeller | Nei |
| NFIF Masters serietabell | Excel | friidrett.no | Nei (ikke i scope nå) |

**Uten disse filene kan ingen loop verifisere noe.** En agent kan hente offentlige PDF-er selv, men du bør laste ned NFIF-Excel-filene manuelt og legge dem i `sources/`, så fasiten er den samme filen forbundet publiserer — ikke noe agenten «fant».

Eksterne kalkulatorer for kryssverifisering (allerede notert i v2.1): worldathleticsscores.com, multieventcalculator.com, howardgrubb.co.uk/athletics/wmatnf23.html. Disse brukes for stikkprøver, ikke som primær-oracle (de kan ha egne feil).

## 4. Loop-kommandoen: hva må være på plass

### 4.1 Prinsippet

En autonom loop fungerer bare når tre ting er sanne:

1. **«Ferdig» er maskinlesbart.** En kommando som returnerer 0 eller ≠0. Ikke «ser bra ut».
2. **Fasiten er uavhengig av koden.** Hvis agenten både skriver kalkulatoren og testene, kan den «fikse» testen i stedet for koden. Fasit må genereres fra kildefilene (Excel/PDF), ikke fra Python-motoren.
3. **Oppgaven er brutt ned i biter agenten kan fullføre i én runde**, med en fil der framdrift persisteres mellom rundene (kontekst nullstilles).

### 4.2 Filer som må finnes i repoet før første loop

```
athletics-points-api/
├── CLAUDE.md                  ← regler agenten alltid leser (se 4.3)
├── LOOP.md                    ← oppgaveliste med [ ]-bokser, agenten oppdaterer selv
├── sources/                   ← kildefiler (Excel, PDF) — READ ONLY for agenten
├── scripts/
│   ├── oracle_tyrving.py      ← Excel → fixtures/tyrving_cases.json (LibreOffice-rekalk)
│   ├── oracle_wa.py           ← PDF/tabell → fixtures/wa_cases.json
│   ├── oracle_wma.py
│   └── oracle_masters.py
├── tests/fixtures/*.json      ← generert, sjekkes inn, IKKE redigeres for hånd
├── tests/                     ← pytest som leser fixtures
├── athletics_scoring/         ← pakken (tom ved start)
├── pyproject.toml             ← pytest, ruff, mypy i [dev]
└── .claude/commands/loop.md   ← selve slash-kommandoen
```

Poenget med `scripts/oracle_*.py` er at de er *separate* fra motoren og skrives/reviewes først. Når en oracle er godkjent, låses fixtures (agenten instrueres om at endring av fixtures er feil).

### 4.3 `CLAUDE.md` — kjernen

Bør inneholde, kort:

- Hva prosjektet er (to setninger) og pekere til BESLUTNINGER.md.
- **Uforanderlige regler:** `sources/` og `tests/fixtures/` endres aldri. En feilende test fikses i `athletics_scoring/`, aldri i testen. Hvis en fixture ser feil ut, stopp og skriv det i LOOP.md under «Blokkert».
- **Ferdig-definisjon:** `pytest -q && ruff check . && mypy athletics_scoring` grønt, og alle bokser i LOOP.md avkrysset.
- Kommandoer for å kjøre tester, regenerere oracle, osv.
- Arbeidsregel per runde: les LOOP.md → velg første uavkryssede oppgave → implementer → kjør tester → commit med `feat/fix(...)` → kryss av → skriv én linje i «Logg».

### 4.4 `LOOP.md` — oppgavelisten

Eksempel på struktur (dette er det agenten jobber seg gjennom):

```markdown
# Status
Sist kjørt: —   Runde: 0   Blokkert: nei

# Fase 0 — Grunnmur
- [ ] pyproject.toml med pytest/ruff/mypy, tom pakke, CI grønn
- [ ] models.py + engine.py (abstrakt) + registry.py

# Fase 1 — Tyrving 2014
- [ ] scripts/extract_tyrving_params.py → data/tyrving_parameters_2014.json (530 kombinasjoner)
- [ ] test_tyrving_params: hver parameter == Excel-celle
- [ ] TyrvingCalculator: simple_quotient (løp/hopp)
- [ ] TyrvingCalculator: three_interval (kast/stav)
- [ ] Edge cases: 0-poeng, 80 %-grense, manuell tidtaking, minutter+sekunder
- [ ] fixtures/tyrving_cases.json (1600) grønn
- [ ] Tyrving mangekamp u/15 (sum)

# Fase 2 — WA Scoring 2025 + Combined Events
- [ ] ...

# Fase 3 — WMA 2023 + Masters mangekamp
- [ ] ...

# Blokkert / spørsmål til Simen
(agenten skriver her og stopper)

# Logg
```

### 4.5 `/loop`-kommandoen

To måter. Den enkle (anbefalt for start): en shell-loop som starter Claude Code på nytt per runde, så konteksten er fersk:

```bash
# scripts/loop.sh
for i in $(seq 1 ${1:-20}); do
  claude -p "$(cat .claude/commands/loop.md)" --allowedTools "Edit,Write,Bash,Read" || break
  grep -q "Blokkert: ja" LOOP.md && { echo "Blokkert — se LOOP.md"; break; }
  git diff --quiet HEAD~1 -- LOOP.md && { echo "Ingen framdrift"; break; }
  ! grep -q "^- \[ \]" LOOP.md && { echo "Alt ferdig"; break; }
done
```

`.claude/commands/loop.md` er prompten for én runde: «Les CLAUDE.md og LOOP.md. Gjør neste uavkryssede oppgave. Kjør testene. Commit hvis grønt. Oppdater LOOP.md. Hvis du er usikker på fasit eller regler, sett Blokkert: ja og forklar. Avslutt.»

Det viktigste er stoppbetingelsene: blokkert, ingen framdrift, alt ferdig, eller maks antall runder. Uten dem brenner loopen tokens på å gå i ring.

### 4.6 Verifisering du må gjøre selv (utenfor loopen)

Loopen kan bare bevise «koden matcher fasiten». Den kan ikke bevise «fasiten er riktig». Du bør:

- Stikkprøve 10–20 Tyrving-verdier mot den offisielle PDF-tabellen for hånd (én gang).
- Stikkprøve WA og WMA mot de eksterne kalkulatorene.
- Sjekke at 80 %-regelen og manuell tidtaking er tolket riktig fra DOC-en — dette er regeltekst, ikke tall, og er det mest sannsynlige stedet for feil.

## 5. Anbefalt rekkefølge herfra

1. **Du:** Opprett repo, klon, flytt kildefilene inn i `sources/`. Last ned NFIF masters-Excel og WA/WMA-PDF-er. (½ dag)
2. **Cowork + du:** Skriv `CLAUDE.md` og `LOOP.md` sammen. Jeg kan lage utkast. (1 time)
3. **Claude Code, én styrt sesjon (ikke loop):** Bygg `oracle_tyrving.py` og generer fixtures. Du reviewer 10 tilfeldige linjer mot Excel. (½ dag)
4. **Loop, fase 0–1:** Tyrving. Forvent 5–15 runder. (1–2 dager)
5. **Styrt sesjon:** Oracle for WA, WMA, masters. Review.
6. **Loop, fase 2–3.**
7. Først *deretter* API-lag, Railway, Vercel.

Kjør loopen på Tyrving alene før du gir den masters og mangekamp. Hvis loopen ikke greier et system med perfekt Excel-oracle, greier den ikke tre systemer med PDF-oracle.
